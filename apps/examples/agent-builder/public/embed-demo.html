Single-origin, roasted the morning it ships.

This page is standing in for a customer's own website. It knows nothing about Kuralle beyond one script tag — no build step, no framework, no npm install.

The entire integration:

<script src="/kuralle-agent.js"></script>
<kuralle-agent agent="support" token="demo-acme"></kuralle-agent>

Click Chat, bottom-right. The widget mints a thread id, keeps it in localStorage, and talks to the same deployment route the builder's preview uses — so the conversation shows up in the builder's Conversations table, pinned to whichever version was live when it started.

Open this page as the other tenant by changing one attribute to token="demo-globex". Same agent id, same thread id format, completely separate conversations and versions.

The demo ships the tenant token to the browser, which is fine here and wrong in production: a real deployment mints a short-lived, thread-scoped token server-side. The widget code does not change.
